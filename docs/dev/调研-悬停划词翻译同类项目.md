## 0. 一句话结论

**你的想法不新，但没被做透。**

- 「悬停鼠标看单词释义 / 划词弹翻译」在 GitHub 上至少有 **10 个以上**在用项目，最早的可以追到 2013 年（划词翻译）。
- 商业化头部产品 **沉浸式翻译** 已经把「鼠标悬停翻译」写进功能列表（支持整页、划词、悬停、输入框四种粒度）。
- 但：**「悬停取单词义」和「悬停整句翻译」在同一产品里都做顺、且针对英文做对（词形还原 / 短语动词 / 语境义）的，仍然基本空白**。日文方向的悬停词典生态（10ten、Yomitan）成熟得可怕，英文方向反而粗糙 —— 这是你真正的机会点。

## 3. 三个最值得精读的项目

### ① MouseTooltipTranslator —— 你的想法最接近的实现，MIT 可商用借鉴
它做的事几乎就是你说的：`Hover or select (highlight) on text to translate`。

工程上已经踩平了一堆坑，值得直接看代码：
- **PDF 支持**：用 PDF.js 把文字层接进 tooltip
- **OCR**：按住 Shift + 悬停在图片上，tesseract.js 识别（漫画场景）
- **双字幕**：YouTube 双语字幕
- **TTS**：按左 Ctrl 朗读
- **输入框翻译**：右 Alt 翻译正在写的内容
- 多浏览器：Chrome / Edge / Firefox 打包

缺点 = 你的机会：**纯机翻**，没有词典义项、没有词形还原、不懂"look up"这类短语动词，也不解释语境义。

### ② 10ten-ja-reader —— 悬停交互的"天花板"，学它的 UX 细节
从 Rikaichamp 改名而来，做日语悬停查词做了 9 年。它的 README 里全是**悬停类产品真正的难点**，逐条都值得抄：
- **智能弹窗定位**（`Smart popup positioning`）+ 竖排文字 + SVG 内文字
- **样式隔离**（`Isolation of styles so that the popup always looks correct`）—— 不被宿主页面 CSS 污染
- **键盘导航**：Shift 切词典、j/k 上下移、c 进入复制模式、e/y/w 分别复制不同格式
- **词形识别**：`食べてた`、`買っとく`、`罰せられる` 这种变形都能还原到原形（这就是英文最缺的 deinflection）
- **专有名词和普通词冲突时自动预览**（`Automatic preview of name entries when there is a better match`）
- **低内存**、词典每周自动增量更新
- 支持**非英语词典**（给过德语示例），已中文本地化

### ③ Yomitan —— 验证了"悬停查词 + Anki 挖词"是刚需
2955 星，Yomichan 的继承者。它证明了一件对产品很重要的事：**悬停查词的终点不是"看懂"，而是"记住"** —— 一键把词 + 原句 + 音频挖进 Anki，形成学习闭环。英文方向目前没有同等体验的工具。

## 4. 这类产品真正的技术难点（不是"弹个框"那么简单）

1. **悬停是模糊输入**。鼠标划过页面时，你不希望每个词都弹窗。成熟做法只有三种：延迟（250–400ms）+ 位移阈值、**修饰键门控**（10ten 默认 Alt/Ctrl，MouseTooltip 用 Shift 做 OCR）、或显式开关。选错就是灾难性误触。
2. **弹窗必须"可进入"**。弹出后鼠标要能移进弹窗里复制、点词、固定，否则体验断裂。需要 `pointer-events`、hover-intent（离开容器后才关，带缓冲三角形）、以及"点击固定（pin）"。
3. **定位**。视口边缘翻转、跨 iframe、Shadow DOM、`position: fixed` 与页面滚动、PDF.js 文本层（div 绝对定位的透明文字）、Canvas/图片文字。这是 10ten 花了最多年份的地方。
4. **英文词形还原**。悬停到的是 `running / ran / better / children / CEOs`，词典里只有原形。没有 lemma + 词性消歧，命中率会低得离谱。
5. **短语动词与习语优先**。`look up`、`give in`、`put off`、`in terms of` —— 必须做**最长匹配**，否则单词级弹窗会给出误导性释义（`look` + `up`）。这是英文悬停产品的分水岭。
6. **请求成本与节流**。如果每次悬停都打翻译 API，成本和延迟都会爆炸。必须做句子/词级缓存、去重、防抖、并发上限。词典走本地是唯一可行解。
7. **隐私叙事**。选中/悬停的文本会外发。企业场景和敏感页面（邮箱、后台）会直接禁用。本地词典 + 可选本地模型是差异化卖点。
8. **MV3 的约束**。Service worker 会休眠、`remote code` 被禁、跨域 fetch 受限。离线词典（大 JSON/WASM）要分片 + IndexedDB 懒加载。

## 5. 现有产品的空白 —— 你真正可以站的位置

按"可验证 + 有付费意愿"排序：

### 空白 A：**从"翻译"升级到"语境义"**（最大机会）
现有悬停产品给你的都是**译文**或**全部义项列表**。你真正想要的是：
> "这个词在**这句话里**是哪个意思，为什么，和它容易混的那个词差在哪。"

这正是 LLM 相对机翻的独占能力，而**目前没有一个悬停产品把它做成默认交互**。nextai-translator 用 LLM 做划词翻译，但输出仍是"翻译"，不是"释义拆解"。

### 空白 B：**英文版的 10ten**
日文的词形还原 + 词性分组 + 音调 + 挖词做成了工业级，英文方向只有机翻弹窗。做一个 `lemma + 短语动词 + 习语 + 搭配 + 例句` 的英文悬停词典，技术路径清晰（有现成数据），且学习者基数远大于日语。

### 空白 C：**零上传 / 离线**
ECDICT（8.6k 星，MIT，77 万英汉词条）足够撑起本地词典。配合本地小模型做整句翻译，"你的阅读内容不出本机"是可讲的故事，也是对 immersive-translate（云端、付费）的正面对撞。

### 空白 D：**悬停的"顺滑度"本身**
沉浸式翻译功能全但重：会改版页面、弹窗占屏、悬停响应慢。把「悬停词 → 秒出、悬停句 → 出译文」的**延迟与不打扰**做到极致，就是一个产品。

### 空白 E：**MV3 时代的重写**
EdgeTranslate 这类老牌停更、社区靠 fork 续命。以一个干净 MV3 架构重做，天然接手存量用户的迁移需求。

## 6. 如果真要做，建议的最小可行形态

```
MV3 扩展
├── content script (all_frames: true) + Shadow DOM 隔离弹窗
├── 触发层：默认「按住 Alt 悬停」；可切换「纯悬停 + 320ms 延迟」
├── 取词层
│   ├── Intl.Segmenter 做词边界（浏览器原生，无需分词库）
│   ├── 最长匹配：短语动词/习语表 > 单词
│   ├── 词形还原：lemma 表（本地）
│   └── 句边界：取当前 block 的文本（悬停整句时）
├── 数据层
│   ├── 本地 ECDICT（分片 + IndexedDB，首次按首字母懒加载）
│   └── LLM：只用于「语境义」和「整句翻译」，句子 hash 做缓存
└── 交互层
    ├── pointer-events: auto（可进入、可选中、可复制）
    ├── 点击/快捷键 pin 住
    └── 生词本 + 导出 Anki（Yomitan 验证过的刚需）
```

**第一版只做一件事**：按住 Alt 悬停英文单词 → 弹窗给出「本句中的义项 + 音标 + 一个例句」，整句悬停 → 一行译文。其余全部砍掉。

## 8. 许可证红线（如果以后要商业化）

| 许可 | 项目 | 能不能抄代码 |
|---|---|---|
| **MIT** | Saladict、MouseTooltipTranslator、ECDICT、floating-ui | ✅ 可以，保留版权声明即可 |
| MPL-2.0 | simple-translate | ⚠️ 改了它自己的文件要开源该文件，可与其他代码共存 |
| GPL-3.0 | 10ten、Yomitan、dictionariez | ❌ 传染，闭源产品只能"读思路"不能"抄实现" |
| AGPL-3.0 | nextai-translator | ❌ 更严格，连 SaaS 都触发 |
| 无 license | immersive-translate、EdgeTranslate | ❌ 法律上默认"保留所有权利"，不可复用 |

**结论：要抄代码就抄 MouseTooltipTranslator（MIT），要抄设计就读 10ten（GPL，只看不抄）。**

## 9. 给你的判断

- 如果目标是**练手 / 自用**：直接装 MouseTooltipTranslator + 沉浸式翻译，先体验 30 天，你会在第 3 天就知道自己到底不满什么。那个"不满"就是你的产品定义。
- 如果目标是**做成产品**：不要做"又一个悬停翻译"。做**「悬停 → 语境义」**（空白 A）或**「英文版 10ten」**（空白 B）。前者是 LLM 时代的新品类，后者是已被验证的需求 + 明确的执行落差。
- 唯一要警惕的：**悬停是个看起来简单、做起来极难的交互**。10ten 一个团队打磨了 9 年，大部分工程量在"弹窗位置"和"词形还原"这两件用户说不出但立刻能感知的事上。
